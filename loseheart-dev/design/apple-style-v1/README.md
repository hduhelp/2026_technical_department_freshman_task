## 阅读方式

每张图按照左到右或上到下阅读，画板编号与以下清单对应。小程序每板 4 个画面，网页和管理端每板 2 个画面。图中照片、人物、日期、数量、联系方式均为演示素材，不代表真实校园信息或官方授权。

图片用于讨论视觉和页面结构。细小字形、占位值和跨图示例数据可能存在生图偏差；字段上限、状态权限与交互以本文件和已确认接口为准。开始实现前应将选定方案整理成可编辑组件与精确尺寸稿。

## 统一视觉与交互规格

| 元素 | 本轮建议 |
| --- | --- |
| 颜色 | 页面 #F5F5F7，内容 #FFFFFF，主文字 #1D1D1F，次文字 #6E6E73，主操作 #0066CC；危险操作用红色并明确动词；状态同时使用文字 |
| 字体 | 系统中文字体；手机正文约 16，桌面正文 14–16；用字号、字重和间距建立层级；允许系统字号缩放 |
| 间距 | 4／8 基础节奏，常用 16／24／32；卡片圆角 12–16；轻分隔和少量阴影 |
| 材质 | 内容区实色；浮动导航或底部面板可少量磨砂；高对比和减少透明度模式使用实色 |
| 操作 | 一屏一个主要任务；按钮按下即反馈；保留清楚的取消与返回；图标操作必须有文本或可访问名称 |
| 触控 | 小程序触控区域至少 44×44，底部操作避开系统安全区；不依赖隐藏手势完成核心任务 |
| 桌面 | 清楚的键盘焦点、表单标签、Tab 顺序；弹层进入后聚焦，关闭后回到触发按钮；可关闭弹层支持 Escape |
| 动效 | 建议正常切换使用轻微、可中断的位移／透明度变化；抽屉从触发方向出现并原路退回；不为普通按钮添加弹跳 |
| 减少动态 | 将大位移、弹性和缩放替换为短淡入或即时切换；加载反馈仍可感知 |

静态图不能验证动效、手势、键盘操作和屏幕阅读器支持。这些是后续交互原型的验收项。

## 不可偏离的页面规则

1. 未登录或未验证用户只看到介绍、登录和状态说明，不预览真实帖子；临时密码强制修改页只允许改密或退出。
2. 类型必须主动选择；名称 1–50 字，地点 1–100 字，描述 1–300 字；纯空白无效。校区只有下沙、绍兴、文一。
3. 日期必填；时间精度有仅日期、具体时间、同日时间段。时间不在未来，区间顺序正确。编辑与发布执行相同规则。
4. 图片可选，最多 6 张、单张不超过 5 MB、JPEG/PNG。首张为封面，支持调整顺序、移除、上传失败后重试。静态详情不能显示可直接删图的控件。
5. 至少一项联系方式，微信／手机号／QQ／其他，每项 1–200 字。大陆手机号 11 位，QQ 5–12 位。同类型可以重复添加；列表不展示联系方式，合法详情展示完整值并支持逐项复制。
6. 每日 3 篇新帖，跨端共用额度，北京时间零点恢复；编辑和重提不扣额度。成功写“已提交审核”，不是“已公开发布”。
7. 审核状态为待审核／通过／退回修改／拒绝／下架；处理状态为寻找中或待认领／已找回或已归还／已撤回。账号禁用导致隐藏属于可见性原因，不能混入处理状态。
8. 内容编辑后隐藏并重审；已完成帖仍可编辑且保留完成状态。只在审核通过、未撤回的本人帖上显示完成与撤销完成。
9. 撤回后不能编辑或恢复，因此撤回前明确确认；完成误操作则提供恢复寻找中或待认领。其他人的详情不出现这些操作。
10. 退回、拒绝、下架均显示原因，可按合同修改重提。审核历史和历史图片只读；历史版本不能使用当前待审操作。
11. 举报只允许他人可见帖子；五种原因中“其他”说明必填，最多 500 字。同一内容版本重复举报显示已提交。举报处理始终关联原始快照。
12. 通知位于“我的”，打开阅读时标为已读。目标不可访问时显示说明，不泄露隐藏帖子信息。没有私聊或订阅通知。
13. 账号资料为只读，没有编辑昵称、头像上传、自助注册和单独解绑。微信首次绑定必须已登录，换绑须验证平台密码；失败保留原绑定。
14. 密码为 8–32 个 Unicode 字符，空格不 trim。改密、换绑成功或退出会使全部旧端登录失效；结果页要求重新登录。
15. 后台退回、拒绝、下架、举报决定、禁用和重置填写原因，最多 500 字。重置仅限普通用户，一次性展示和复制临时密码，线下交付，不写通知或日志，不自动重试。
16. 提交失败保留输入；变更冲突提示重新查看，不自动覆盖。提交中防重复，并保留明确反馈。破坏性操作确认说明具体对象与后果。
17. 原型不增加分类、聊天、好友、点赞收藏、认领审批、地图存放点、AI 审核、数据大屏、角色管理或导出功能。

## 生成与后续讨论

使用内置 image_gen 生图工具；主提示词、各端构图和逐板页面内容保存在 [prompts.json](prompts.json)。定向修订提示词保存在 [revisions.json](revisions.json)。

先讨论三个决定：首页卡片的信息密度是否合适；发布是否保留单页分组表单；后台队列与详情并排是否便于审核。确定后再做可编辑稿或实现，不把这套生成图当成已验证可用的前端。
